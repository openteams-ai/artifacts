Cloud provider parity: what's portable across AWS, GCP and Azure

Goal: stick to features every major provider supports, so the same Kubernetes manifests work everywhere with only a per-cloud StorageClass / NodeClass mapping underneath. The Agnostic baseline column is the lowest common denominator to build against.

Build to this

  • StorageClasses named by role (block-rwo, shared-rwx), mapped per cloud; charts reference the role name only.
  • Zonal RWO block with WaitForFirstConsumer, expansion and CSI snapshots.
  • RWX over NFS CSI, explicitly sized.
  • Object storage via an abstraction layer, not hardcoded S3.

Avoid in shared code

  • Multi-zone replicated disks (no AWS equivalent).
  • Cross-zone clones — clones are same-zone on every cloud.
  • OpenZFS-specific features; elastic-sizing assumptions from EFS.

Build to this

  • Workloads schedule on resource requests and well-known labels (kubernetes.io/arch, topology.kubernetes.io/zone) only.
  • NodePool / ComputeClass / node-pool definitions live in the per-cloud layer, never in app charts.
  • Every container sets requests; no privileged pods or hostPath — passes the strictest managed mode.

Avoid in shared code

  • Cloud-specific spot / capacity labels.
  • Karpenter NodePool CRDs as a portable API — GKE doesn't have them.

Build to this

  • Zonal block is the only storage built in on all three managed modes.
  • Shared NFS and object mounts work everywhere, but are add-ons on EKS Auto Mode (and Blob CSI on AKS) — install them in the per-cloud layer.

Avoid in shared code

  • The NetApp/Trident high-perf tier on managed modes — use standard node groups / pools where that tier is needed.
